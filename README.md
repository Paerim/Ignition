# HUB 4x4 Quality Dashboard (Ignition Perspective)

Ignition 8.1 project with a Perspective version of the HUB 4x4 quality dashboard.

## Contents

| Path | What |
|---|---|
| `com.inductiveautomation.perspective/views/HUB4x4/QualityDashboard` | Main dashboard (page `/`) |
| `.../views/HUB4x4/Components/*` | Reusable views: KpiTile, BarRow, LineStatusRow, AbnormalItem |
| `.../views/HUB4x4/Popups/AbnormalDetail` | "More detail" popup |
| `ignition/script-python/hub4x4/data` | Data provider (`hub4x4.data.getDashboard`) |
| `db/hub4x4_schema.sql` | Tables used when reading from a database |
| `assets/layout/` | Line layout picture and per-point highlight overlays (embedded into the view) |
| `tools/make_layout_assets.py` | Rebuilds the overlays from `line_layout_source.png` (needs Pillow, numpy, scipy) |
| `tools/build_views.py` | Generator for the view JSON. Edit layout here, then run `python3 tools/build_views.py` |

## Dashboard sections

- KPI: Total Plan, FG, OK, NG, PPM, Repair status (Total / Closed / On Process)
- Period buttons Hourly / Daily / Weekly / Monthly + date range (from / to)
- Inspection Item Point A-F: click to switch the control chart (UCL / LCL / Target, warning points in orange)
- Line Layout: picture of the line; the stations of the selected Inspection Item are highlighted
  (A: 110A/110B, B: 120A/120B, C: 130A/130B/130C, D: 140A/140B/140C, E: 125A/125B, F: Q)
- Production Line: performance % with green (>=97) / orange (>=90) / red dot
- Total NG tendency, OP Performance, Top 5 Defects, Repair cause
- Abnormal List (NG + Repair) with a "More detail" popup

Data refreshes every 10 seconds (`now(10000)` in the `view.custom.data` binding).

## Install

1. Copy this folder to `<Ignition>/data/projects/<ProjectName>/` (or zip it and use Gateway → Projects → Import).
2. Gateway scans projects automatically; or open the project in the Designer.
3. Open `http://<gateway>:8088/data/perspective/client/<ProjectName>/`.

## Simulated data → real database

The dashboard runs on simulated data by default. To use a database:

1. Create the tables in `db/hub4x4_schema.sql` and feed them from your PLC/MES (Transaction Groups, gateway scripts, etc.).
2. In `hub4x4/data` set `USE_DB = True` and `DB = "<your DB connection name>"`.

Control-chart limits per point live in `LIMITS` in the same script (the DB version reads them from `hub_inspection`).
PPM is calculated as `NG / FG x 1,000,000`.

## Changing the line layout picture

1. Replace `assets/layout/line_layout_source.png`.
2. Update the station centres in `STATIONS` and the point mapping in `POINTS` (`tools/make_layout_assets.py`),
   and `POINT_STATIONS` in `tools/build_views.py`.
3. Run `python3 tools/make_layout_assets.py` then `python3 tools/build_views.py`.

# Receiving Station (Smart TV / HMI / Handheld)

| Page | View | Device | What |
|---|---|---|---|
| `/receiving` | `Receiving/Overview` | any | Links to the three screens |
| `/receiving/tv` | `Receiving/SmartTV` | Smart TV 1920x1080 | 2 dashboards on one screen: (1) Truck Receiving Monitoring, (2) Mini WMS |
| `/receiving/hmi` | `Receiving/HMI` | HMI 800x480 | Truck Arrive / Truck Departure buttons + Supplier dropdown |
| `/receiving/handheld` | `Receiving/Handheld` | Handheld (mobile) | CCR orders split per supplier, scan parts, confirm receipt |

Components: `Receiving/Components/*` (TruckRow, MiniKpi, ModelBar, SeqChip, HmiTruckCard, OrderCard, ItemRow).
Data: project script `receiving.data` (`ignition/script-python/receiving/data`). Views are generated by
`python3 tools/build_receiving_views.py` (run from `tools/`).

## Smart TV
- **Truck Receiving Monitoring**: per supplier (with delivery pattern, e.g. `ABC 1:2:2`) and truck: Arrive Plan/Actual,
  Departure Plan/Actual (actual in yellow = stamped from HMI / PLC), Status pills **On time / Delay / Advance**
  (±`TOLERANCE_MIN` = 5 min against the plan; a truck not arrived after plan + 5 min shows Delay).
- **Mini WMS**: today's KPIs, status of all supplier orders, units per model, the CCR production Sequence
  (`Result ABCAAB...`) and the parts to receive per order (Item code / name / supplier / qty / received / remaining).

## HMI
- Choose a Supplier (and optionally a Truck; default = next truck). **Truck Arrive** / **Truck Departure** writes the
  actual time, which is shown immediately on the Smart TV. Buttons fade out when that supplier has no truck waiting.
- For a PLC signal instead of the button, call `receiving.data.onPlcSignal('ABC', 'arrive')` from a tag change script.

## Handheld
- **รับออเดอร์จาก CCR** pulls new CCR orders. A CCR order is a Sequence (`A`/`B`/`C` = model per unit); it is
  exploded with the `BOM` into one receiving order per Supplier (which parts / how many each supplier delivers).
- Tap an order to see its parts, scan (`T0001` = +1, `T0001*5` = +5; keyboard-wedge scanners work, the field submits on Enter),
  then **ยืนยันรับสินค้า**. It confirms only when every part is complete; status becomes **รับสินค้าสำเร็จ**.
- CCR can also push orders directly: `receiving.data.receiveCcrOrder('CCR-20261119-03', 'ABCAAB...')`
  (gateway message handler, WebDev endpoint, tag change ...).

## Simulated data → database
Runs on in-memory simulated data (resets daily). For a database: create `db/receiving_schema.sql`, fill
`rcv_truck_plan` each day, let CCR insert into `rcv_ccr_inbox`, then set `USE_DB = True` and `DB` in `receiving/data`.
Suppliers, parts and BOM are the `SUPPLIERS`, `PARTS`, `BOM` constants in the same script.
